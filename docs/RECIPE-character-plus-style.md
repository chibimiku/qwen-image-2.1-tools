# 固定角色 + 指定画风：双图配方模板

**用途**：把「一个固定角色的形象」稳定地画进「另一张参考图的画风」里，用于系列插画、
galgame CG、约会壁纸这类需要**同一角色反复出现、画风统一**的场景。

**一句话做法**：两张图分别喂不同角色 —— `<image1>` 管身份、`<image2>` 管画风，
prompt 里用**短样式词**（不是长描述）+ **明确的分工句**，尺寸**显式固定**。

> 依据：本项目 300 张实测（见 [`EXPERIMENT-style-migration-RESULTS.md`](EXPERIMENT-style-migration-RESULTS.md)）。
> 核心结论是「只上传参考图几乎不传递画风」（画风分 1.42/5，基线 0），
> 而「长样式词 + 参考图」会把参考图的内容一起拉进来（内容分掉到 1.89、泄露 3.69）。
> 唯一同时守住内容和画风的是**双图分工 + 短样式词**。

---

## 一、这个配方解决什么、不解决什么

**解决**：让固定角色的**身份特征**（发色/瞳色/发型/标志性配饰/服装）在系列图里保持一致，
同时让**渲染技法**（线条、上色、光效、质感）来自另一张参考图。

**不解决**：

- **不保证构图一致**。同 seed 也不代表同构图，t2i 与带图推理走的是不同路径。
- **不能靠"多给参考图"来加强画风**。参考图越多，内容越容易被替换。
- **换不了线条与结构层面的画风**。双图路线实测画风分 2.87/5，
  收益集中在上色与氛围；真正换掉整套渲染语言需要走「参考优先 + 短词」的单图路线，
  代价是身份漂移风险上升。

## 二、三步准备

### 步骤 1：写「角色圣经」（Character Bible）

把角色的**可辨识特征**写成一段固定文本，**每一张都原样复用**。
不要每次重写 —— 重写等于换人。

要点：只写**视觉可辨识**的东西（发色/瞳色/发型/配件/服装/体型），
不写性格、背景故事、情绪。控制在 60–90 个英文 token（约 250–370 字符）。

模板：

```
The character is <性别/年龄感>, with <发型长度 + 发色 + 发质/卷直 + 特殊发型结构>,
large <瞳色> eyes, and <标志性配饰>. She wears <上衣: 颜色 + 款式 + 材质>,
<下装/裙: 颜色 + 款式 + 长度>, and <鞋/袜>. <体型/比例兜底句>.
```

> 本项目实例（角色=搭配师）的填法见第四节。

### 步骤 2：给画风参考图做「风格体检」

**这一步不能省。** 参考图里只要有**具体的、完整的主体**（人物、画框、器物），
模型就会把它整块搬进你的画面 —— 实测里 sakurapion 的参考图复刻了水果芭菲、
fuzichoco 的参考图连镀金画框和白鸽一起照搬。

体检要回答两个问题：

1. **这张图里有没有"主角级"的主体？**（人、宠物、器物）
2. **去掉主体之后，还剩什么可借？**（线条 / 上色 / 光效 / 质感 / 色调 / 背景母题）

把答案写成「借什么、不借什么」两张清单。**凡是可能被整块搬走的元素，
都要在 prompt 里逐条点名禁止** —— 泛泛写 "do not copy the reference content" 不够用。

### 步骤 3：定分辨率和长度预算

**显式传 `width` / `height`**。不传的话管线用**最后一张**参考图的朝向推比例，
等于把画风图的比例强加给角色。

长度预算按 **文本 token + 参考图 vision token 合计** 算（硬上限 **9216 个位置**）：

| 参考图边长 | vision token |
|---|---|
| 512 | 256 |
| 1024 | 1024 |
| 1280 | 1600 |
| 1536 | 2304 |
| 1920 | 3600 |

两张约 1024 级参考图 ≈ 2000–2600 token，**文本只剩约 6600–7200 token**。
超限不是干净报错，而是把服务打停，必须重启。用 `POST /v1/tokenize` 先算。

## 三、配方本体

### 3.1 参数

| 参数 | 取什么 | 为什么 |
|---|---|---|
| `image`（重复两次） | **先角色图、后画风图** | 顺序即 `<imageN>` 编号，prompt 里靠它点名 |
| `width` / `height` | **显式填**，用你最终要的尺寸 | 不填则跟随最后一张参考图的比例 |
| `num_inference_steps` | 30–40 | 40 是官方默认，成品用 40 |
| `true_cfg_scale` | **1.0** | 官方按无引导设计；调高耗时翻倍且画面变闷 |
| `negative_prompt` | **不填** | CFG=1 时机制上不起作用，填了只是误导 |
| `seed` | 先固定一个做验证 | 出图后服务端不回填 seed，要复现得自己记 |
| `num_images_per_prompt` | 1 | 配对比较时才有意义设 >1 |

### 3.2 prompt 结构（四段，顺序别换）

```
[第 1 段 分工声明]  一句话说清两张图各管什么，并声明内容优先
[第 2 段 短样式词]  从画风参考图提取的技法描述，不是画风图内容的复述
[第 3 段 禁止清单]  逐条点名画风图里不许被搬走的元素
[第 4 段 场景描述]  这一张要画什么（角色圣经 + 动作 + 场景 + 镜头）
```

### 3.3 英文模板（可直接用）

```
Render this in the art style of the provided style reference, applying its technique only.
<image1> defines the character's identity — hair colour, hairstyle, eye colour, facial
features and outfit must be preserved exactly. <image2> is a STYLE SAMPLE ONLY: borrow its
linework, colouring method, light rendering and texture.

<STYLE_SHORT: 2–3 句，只写技法>

Do NOT copy from <image2>: its character, its hair colour or eye colour, its clothing,
its props, its instruments, its accessories, its background, its frame or composition.

<CHARACTER_BIBLE>. <动作/表情>. <场景/地点/时间>. <镜头与构图: e.g. wide cinematic
composition, subject placed off-centre, full body / upper body>. Soft depth of field,
no text, no watermark, no border.
```

### 3.4 中文对照模板

```
画风按参考图 <image2> 的技法来。角色身份以 <image1> 为准 —— 发色、发型、瞳色、
五官与服装必须逐项保持。除画风技法外，不要从 <image2> 借用任何角色、服装、道具、
乐器、配饰、背景或画框构图。

<STYLE_SHORT 的中文版>

<角色圣经>。<动作>。<场景>。<镜头>。
```

> **不要**自己加 "keep the aspect ratio" 这类句子 —— 那是我服务端不认的字段
> （属于官方 PE 层，本服务跑原始管线）。比例靠显式传宽高。

## 四、本项目的具体填法（角色 = 搭配师，画风 = 艺术风格参考）

### 4.1 角色圣经

```
The character is a young woman with shoulder-length wavy indigo-blue hair, a small side
bun tied at one side, and a small white flower hairpin above one ear, large blue-violet
eyes, and soft rounded facial features. She wears a white puff-sleeve blouse under a blue
denim pinafore dress with two gold buttons at the waist, the pleated skirt fading from
sky blue at the waist to pale mint at the hem with a white ruffled underlayer, and blue
bow-embellished Mary Jane heels.
```

### 4.2 画风参考图的「借 / 不借」清单

这张参考图是一个**完整的海报式构图**（躺在星空舞台上的白金发少女），
主体强度高，必须严格分工。

**借（技法）**：

- 高饱和但柔和的色彩，冷紫/深蓝底 + 暖金光点
- 发光粒子与星点散布（bloom / glow）
- 大范围柔和渐变光，边缘轻微过曝
- 细腻但明确的黑线，发丝与布料有明显高光
- 深色背景压边、主体受光的"舞台感"打光

**不借（内容，逐条禁止）**：

- 白金色长发 / 绿色眼睛 / 那条白裙 / 长筒袜 / 吊带
- 星空舞台地板 / 星座连线 / 悬浮三维星星 / 菱形宝石
- 小提琴琴弦与琴弓等乐器元素
- 原图的仰躺姿势与对角线构图

### 4.3 本组合的短样式词

```
Luminous anime illustration with a polished galgame CG finish: crisp clean linework,
rich saturated colour with soft pastel gradients, glowing particle sparkles, wide soft
bloom on highlights, dramatic rim light separating the subject from a deep contrasty
background, delicate fabric and hair highlights.
```

### 4.4 为什么不能省掉「协议 3.3」的两段

实测规律很直接：**参考图里的主体越具体，越会被整体搬走。**
本组合的风险点集中在三处 —— 白金发色、星空场景、乐器与星点道具。
不逐条点名禁止，最容易出现的结果是"角色被换成白金发少女，站在星空舞台上"，
也就是**画风借到了、但角色丢了**。

## 四·补、本组合的实测结果（2026-10-01，26 张）

配方按第三章发出后，做了五组对照。**结论和最初预期相反，这一节比上面更重要。**

### 4b.1 五组对照（同一场景、同一 seed 42，只改喂了哪张图）

| 组 | 喂了什么 | 结果 |
|---|---|---|
| **A 纯文本** | 不给任何参考图，只发角色圣经 + 样式词 | **暗调夜景 + 轮廓光 + 光点最完整**，发色发饰正确 |
| B 只给角色图 | `<image1>` only | 有夜感与边缘光，但**鞋子画错了**（参考图鞋型没吃进去） |
| C 只给画风图 | `<image2>` only | **角色被换掉**：紫发、双丸子、体型变小、鞋子带袜子 → 画风图**不能**用来固定角色 |
| D 双图 + 基础样式词 | `<image1>` + `<image2>` | 身份正确、鞋子正确，但**画面被拉成明亮白天**，夜感与光点丢失 |
| E 双图 + 强化样式词 | 同上，但把"光学描述"写进样式词 | **夜感与光点回来了**，鞋子正确 —— 这一档最接近目标画风 |

**三个反直觉的发现：**

1. **画风参考图并不传递"画风"，它传递它自己的主体。**
   C 组（只喂画风图）是最直接的证明：出来的角色是参考图那一类，不是我们的角色。
   所以双图里 `<image2>` 的真实作用是"提供光学与质感线索"，**不是**"提供画风身份"。

2. **真正控制画风的是样式词，不是参考图。**
   加参考图后画面反而变亮、失去夜感（D 组）；把样式词从抽象词换成
   具体的光学描述（"暗底 + 亮主体 + 轮廓光 + 密集光点 + 高对比高光"）之后，
   同一个参考图就给出了正确的暗调（E 组）。**旋钮在文字这一侧。**

3. **角色立绘是纯白背景，会把画面拉向"平光、明亮"。**
   这是 D 组白天化的最可能原因：立绘本身在教模型"白底、平光的产品图"渲染方式，
   与参考图的暗调光学直接冲突。E 组之所以能压回来，是因为光学描述被写得足够具体。

### 4b.2 稳定的失败模式：参考图主体作为**第二个角色**出现

跨 seed 检查（同一场景、强化词、seed 42 / 1234 / 20260927）：

- seed 42、1234：干净，单角色。
- **seed 20260927：画面里出现两个人** —— 我们的角色，加**参考图里那个白金发少女本人**
  （白裙、吊带袜一起照搬）。这是跨角色泄露，不是风格化。
- 12 张正片里也出现过一次同类事故（06-sunset-bridge 早期版本出现两个"同一个角色"）。

**结论：这个组合有稳定的失败模式，任何一张都不能"跑一次就交付"。**

### 4b.3 因此修正后的操作建议

| 场合 | 建议 |
|---|---|
| 要**最稳**的画风 | 走 **A 纯文本**：不给参考图，把光学描述全写进样式词。代价是服装细节靠文字，容易画错（如鞋子） |
| 要**服装准确 + 画风正确** | 走 **E 双图 + 强化样式词**，**每个场景至少跑 3 个 seed**，逐张过验收清单 |
| 要快速定调 | 先用 A 纯文本试场景与光线，定下来后再用 E 补服装细节 |
| **不要用** | C（只给画风图）—— 角色必丢 |

**跨 seed 是硬要求，不是可选项。** 本组合的失败是"整张作废"级别的
（多出一个人），不是在原有基础上变差，所以不能靠"看着差不多"放过。

### 4b.4 宽屏尺寸的硬边界

带参考图的请求按"编辑"红线判（`3.65 × MP²`）。
**宽屏能跑的上限比竖版低**：竖版实测 1.92MP 通过，而 16:9 在 **1600×896（1.43MP）**
以上会被同比例缩回来：

| 请求 | 实际得到 |
|---|---|
| 1536×864（1.33MP） | 原样 |
| **1600×896（1.43MP）** | **原样 —— 这就是宽屏天花板** |
| 1600×1024 | 1504×960 |
| 1600×1152 | 1408×1024 |
| 1792×1024 | 1600×896 |
| 1920×1104 → 2048×1152 | 1600×896 |

**宽高必须是 64 的倍数**（1008→992、1104→1088、2752×1536→2560×1440），
否则会被吸附；一切以响应里的实际 `size` 为准。

## 五、执行顺序（别跳步）

1. **出对照图**：只传角色图、不加画风图，跑一张。确认角色圣经本身够用。
2. **出双图**：同一 seed、同一场景，加画风图。和上一步并排看 ——
   **身份变了没有？场景被星空取代了没有？**
3. **同一场景跑 3 个 seed**：只留一个 seed 满意的结果不算数，
   实测同组跨 seed 的内容与泄露波动比画风分大得多。
4. **不满意先换参考图，不是改配方**。配方只调三个旋钮：
   短样式词的措辞、禁止清单的详略、宽高。
5. **放量前算一遍 token**：`POST /v1/tokenize`，确认合计 ≤ 9000 位置。

## 六、成品验收清单

逐张过，有一项不过就重跑（换 seed 或换参考图）：

- [ ] **发色瞳色**没变（这是最容易漂的两项）
- [ ] **服装结构与配色**没变（款式、扣子数、裙摆渐变方向）
- [ ] **标志性配饰**在（发饰、鞋）
- [ ] **场景是你要的**，不是画风图里的场景
- [ ] **没有画风图里的道具**（星点可以留，星座连线/乐器/宝石不要）
- [ ] **画风确实变了**：和对照图比，上色和光效看得出是同一套
- [ ] **人体结构正常**（手、腿、颈肩）—— 画风迁移不解决结构问题

## 七、常见失败与对应处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 角色发色变成参考图的颜色 | 分工句不够硬 | 把 `<image1>` 那句提到最前面，并在禁止清单里点名发色 |
| 背景变成参考图的背景 | 禁止清单没列全 | 逐条列出参考图的背景母题，不要泛写 |
| 画风几乎没变 | 短样式词太抽象，或参考图主体太抢 | 把样式词改成具体技法词（linework / bloom / rim light）；必要时换参考图 |
| 画面出现参考图里的人 | 参考图主体强度过高 | 换一张无主体的风格板，或裁掉人物只看技法区 |
| 构图像海报、人物很小 | 参考图的构图被继承了 | 禁止清单加"frame / composition / layout"，并在场景段显式写镜头 |
| 超长报错后服务 500 | prompt 撞了 9216 位置上限，CUDA 上下文被打坏 | 重启服务；先用 `/v1/tokenize` 卡住长度 |

## 八、可复制的完整请求（curl）

```bash
BASE=http://127.0.0.1:6006        # 实例内；从本机走隧道同理
KEY=...                            # 从 tools/.qwenkey 读，不要写进脚本

curl -s "$BASE/v1/images/generations" \
  -H "Authorization: Bearer $KEY" \
  -F "prompt=<把 3.3 的四段拼好>" \
  -F "image=@角色-搭配师.png" \
  -F "image=@艺术风格参考.png" \
  -F "width=1920" -F "height=1104" \
  -F "num_inference_steps=40" -F "true_cfg_scale=1.0" \
  -F "seed=42" \
  -o out.png
```

> `image` 字段**按上传顺序**编号：第一个是 `<image1>`，第二个是 `<image2>`。
> 顺序反了就等于把身份和画风对调，结果会完全不对。

## 九、适用范围与已知边界

**适用**：角色需要跨图保持一致、画风需要统一的系列插画；双人/多主体合成；
带参考图的姿势与服装编辑。

**已知边界**（本轮实测结论，不是猜测）：

- 双图路线的画风收益**集中在渲染与氛围**，换不掉线条与结构层面的画风。
- 跨 seed 波动明显，3 个 seed 全过的组合在本轮只有少数几个配方达到。
- 参考图主体强度与泄露率正相关（本轮的泄露率从 25% 到 69% 不等，
  差的都是参考图里有明确主角的）。
- **未验证**：跨 GPU/跨 diffusers 版本的可复现性；参考图主体占比与泄露的定量关系；
  无主体风格板能否在保住画风的同时压低泄露（本轮没做）。

复现与参数细节见 [`EXPERIMENT-style-migration-RESULTS.md`](EXPERIMENT-style-migration-RESULTS.md)。
