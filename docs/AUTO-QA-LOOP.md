# 出图自检回路：视觉 LLM 判定 → 自动改 prompt 重跑

**做什么**：出图后把图发给视觉模型判定质量；不合格就让模型**在上一版 prompt 的基础上**做最小编辑
（改场景段 / 换样式词档位 / 换参考图组合 / 换 seed），再重跑。最多 N 轮，合格即停。

**在哪**：控制台的「AI 自检（视觉 LLM 判定 → 自动改 prompt 重跑，最多 N 轮）」面板。

---

## 一、先配 key

面板里填三样：

| 字段 | 默认 | 说明 |
|---|---|---|
| 接口 Base URL | `https://api.deepseek.com` | 任何 OpenAI 兼容端点都行 |
| 模型 | `deepseek-flash` | DeepSeek 的视觉模型；旧名 `deepseek-v4-flash-vision-exp` 已下线 |
| API Key | 空 | **只往服务端发，页面从不回显** |

点「保存配置」写入实例上的 `vision.env`（**权限 600，已在 .gitignore 里**），
再点「测试连通」验证 —— 测试只发一个纯文本请求，**不传图**，省 token 也不外传内容。

> **key 的安全约定（改动前先读）**
> - 服务端只回 `has_key` 布尔值，**任何接口都不回显 key**；
> - 日志与错误信息里不出现 key（DeepSeek 自己也把它脱敏成 `****6789`）；
> - 前端 `loadVisionConfig` **不消费** `api_key` 字段，输入框永远空白；
>   这一条由 `tools/check_ui_tokenize.py` 静态把关（连"赋非空值"都算失败）；
> - 传空 key = 不修改已保存的；要清掉用 `clear_key: true`。

---

## 二、跑一条回路

面板里设两个参数，然后点「开始自检回路」（**独立按钮**，不混进普通「生成」，
因为回路会跑多轮、耗时数分钟）：

| 参数 | 默认 | 说明 |
|---|---|---|
| 最多修订轮数 N | 3 | 含首轮；上限 8 |
| 合格分数线 | 7.0（0–10） | 判定分数 ≥ 它就算过，直接停 |

参考图按上传顺序喂：**第一张当角色图，第二张当画风图**。

跑起来后可以离开页面 —— 任务在服务端继续；回来时状态还在。

---

## 三、回路怎么判断、怎么改

判定与修订都是**固定 prompt**（见 `service/autoloop.py`），并且都要求模型只输出 JSON。

### 判定（`JUDGE_SYSTEM`）

按 A/B/C 三类共 22 项核对，**先人体结构、再语义内容、最后渲染画质**：

- **A 人体结构**：A1 手指形态 / A2 手臂 / A3 腿 / A4 脚与鞋 / A5 头颈肩 / A6 五官 / A7 躯干 / A8 与道具的接触
- **B 语义内容**：B1 人数 / B2 身份 / B3 服装 / B4 鞋型 / B5 道具 / B6 场景 / B7 动作 / B8 画风图泄露 / B9 角色图泄露
- **C 渲染画质**：C1 过曝 / C2 欠曝 / C3 糊 / C4 复制粘贴 / C5 文字水印

严重度 **P0**（人体崩坏或人数不符，整张作废）→ **P1** → **P2** → **P3**。

### 修订（`REVISE_SYSTEM`）

**只允许改四处**，其余原样保留：

| 字段 | 取值 | 什么时候用 |
|---|---|---|
| `new_scene` | 文本 | 改写场景段（必须仍含完整角色圣经）。手部缺陷就写清每只手在做什么；人数错就加 `Exactly one girl in the frame, alone`；过曝就点名 3–4 个环境元素 |
| `style_tier` | `base` / `boost` | 画面太亮、丢了暗调与光点 → `boost`；画风够了但内容被压 → `base` |
| `ref_mode` | `char+style` / `char` / `style` / `none` | 身份漂移 → 留 `char`；画风没进来 → `char+style`；参考图内容泄露 → 退到 `char` 或 `none` |
| `seed` | 整数 | 同类缺陷反复出现时换 |

模型觉得改不动了会返回 `giveup`，回路立即停（不白跑后面几轮）。

### 三处防"模型自由发挥"的约束

1. **越界值被丢弃**：`style_tier` / `ref_mode` 只认枚举值，
   模型自创的 `ultra-mega`、`triple-image` 一律清空，不会写进 prompt。
2. **自相矛盾不信**：`ok=true` 却同时报了缺陷 → 强制判为不合格。
3. **解析失败保守处理**：判定解析不出来 → 按**不合格**处理（不当成通过）；
   修订解析不出来 → `giveup`（宁可停，不要瞎改）。

---

## 四、为什么这么设计（每条都对应踩过的坑）

| 决定 | 原因 |
|---|---|
| 修订是"基于上一版**编辑**"而非重写 | 重写会丢掉已有约束，且出问题无法归因 |
| 只改四处、且值受枚举约束 | 自由发挥的 prompt 改法不可复现，也说不清是哪一处起了作用 |
| 每轮产物、判定、修订记录全部落盘 | 事后要能回答"为什么第 2 轮把样式词换了" |
| 图片只能放 `user` 消息 | DeepSeek 官方限制：放 system/assistant 会 400 |
| 用 base64 data URL 而不是外链 | 本地文件最省事；单图上限 32 MiB，出图远小于它 |
| `detail` 默认 `high` | 判手指/鞋带这类结构需要原图；`low` 会缩到 512² 丢细节 |
| 独立按钮而非并入「生成」 | 回路跑多轮、耗时数分钟，混进普通生成会让人误以为卡住 |

## 五、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/vision/config` | 读配置（**只回 has_key**） |
| POST | `/v1/vision/config` | 写配置；空 `api_key` = 不改，`clear_key` = 清 |
| POST | `/v1/vision/test` | 连通性自检（纯文本，不传图） |
| POST | `/v1/auto/start` | 启动回路（multipart，同 `/v1/images/generations`，多 `max_rounds`/`pass_score`） |
| GET | `/v1/auto/status/{job_id}` | 进度：逐轮日志、判定、修订记录、产物路径 |
| GET | `/v1/auto/list` | 近期任务 |
| POST | `/v1/auto/stop/{job_id}` | 请求停止（**每轮开头**检查，不硬中断正在跑的出图） |
| GET | `/v1/auto/file/{job_id}/{name}` | 取某轮的图（路径限定在该任务目录内，防穿越） |

## 六、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 「测试连通」报 401 | key 无效 | 重新粘一次；服务端报错里会脱敏显示 key 尾 4 位 |
| 启动回路报 400 | 还没配 key | 先保存并测试通过 |
| 回路状态 `failed` | 判定阶段出错 | 看 `status.log` 最后一行，通常是网络或凭据 |
| 跑完没通过 | 到了 N 轮仍低于分数线 | 看 `history` 里哪轮分数最高，那轮的图在 `run_dir` |
| 想换 key | —— | 直接粘新的覆盖，不用先清空 |

产物落在实例的 `auto-runs/<job_id>/`（每轮的图 + 判定 JSON），**不入库**。

---

## 七、已知边界

- **判定质量取决于视觉模型**。本项目的 `service/anatomy_check.py` 那个本机
  2.2B 模型校准没过（见 `EXPERIMENT-style-migration-RESULTS.md`），所以这里走 API。
- **修订只改 prompt 与四个旋钮**，不会自己换画风参考图、不会重画参考图。
- **回路不保证收敛**。N 轮后仍可能不达标 —— 那时它会停在**得分最高**的那轮，
  并把每轮的图都留在 `run_dir` 里供人挑。
- **未验证**：换非 DeepSeek 端点（只要 OpenAI 兼容即可，但没实测）；
  超过 8 轮的收敛性；判定分数与实际人眼评价的相关性（需要一批人工标注做校准）。
