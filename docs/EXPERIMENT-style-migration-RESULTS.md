# 参考图 + 样式迁移实验 —— 结果与结论

实验设计与清单见 `exp/style-reference-migration-20260927/TEST_PLAN.md` 与 `manifest.json`。
本文是**实测结果与结论**：330 张真实出图的逐图评分、跨 seed 稳定性、内容泄露率，
以及据此给出的最小移植方案。

> 原始产物（出图、逐任务请求/响应、评分表、画廊、对照图）在
> `exp/style-reference-migration-20260927/`，**不纳入版本控制**（体积约 1.5 GiB）。
> 本文把可独立成立的结论带进仓库；要看图或复核请用那包。

**一句话结论：参考图与样式文字本身几乎不传递画风；真正把画风推起来的是
「参考图 + 角色说明 + 样式词」的 D/E/F 这一档，但同一条线也是泄露开关 ——
连明确写着 no person 的静物主题都被画进了人。在「内容 ≥4 且泄露 ≤1 且质量 ≥3」
的约束下，只有 waterink-style 还能同时保住画风与内容。**

## 2. 评分口径

四维各 0–5，逐图记录并附可见证据（证据代码表见实验包 `analysis/evidence-codes.md`）：

| 维度 | 含义 |
|---|---|
| style | 渲染技法相对同风格 A 基线的位移：线条、上色方式、光影、纹理、五官/头发抽象度 |
| content | 请求的身份/发色/瞳色/服装/道具/场景/数量是否保住 |
| leakage | 参考图**自身内容**（其主角、室内、道具、背景、装饰母题、画框构图）被搬入画面的程度 |
| quality | 完成结构、连贯性、瑕疵、单幅完整性 |

**单图可接受 = content ≥ 4 且 leakage ≤ 1 且 quality ≥ 3。**
评分先做盲评（打乱顺序、只给编号，逐格打完后才揭盲），其余单元按同一口径读对照表。

## 3. 六组对照结果（全 5 风格汇总，n=45/组）

| 组 | 风格均值 | 内容均值 | 泄露均值 | 质量均值 | 可接受率 |
|---|---|---|---|---|---|
| A 无样式 | 0.00 | 4.98 | 0.00 | 3.98 | **100%** |
| B 仅样式短词 | 1.84 | 4.60 | 0.11 | 3.98 | 98% |
| C 仅参考图 | 1.42 | 4.69 | 0.27 | 4.00 | 93% |
| D 长词+参考图 | **3.76** | **1.89** | **3.69** | 3.91 | **16%** |
| E 短词+参考图 | 3.13 | 3.20 | 2.76 | 4.00 | 27% |
| F 参考优先 | 3.36 | 3.36 | 2.60 | 4.07 | 31% |
| G 仅内容图（双图基线） | 0.00 | 4.27 | 0.00 | 4.00 | 100% |
| H 内容图+画风图 | 2.87 | 4.33 | 1.07 | 4.00 | 73% |

**三条读得出来的结论：**

1. **只上传参考图（C）几乎不改变画风**：风格均值 1.42（A 定义为 0），却拿到全部组里
   最好的内容分（4.69）与零泄露。只给样式文字（B）也只有 1.84，而且**比 C 还高一点** ——
   纯文字比参考图更容易被模型接住。
2. **D/E/F 才是画风开关，也是泄露开关**：D 的风格均值 3.76 但内容只有 1.89、
   泄露 3.69（泄露≥3 占 82%）。E/F 居中。
3. **双图分工（H）能守住内容但换不来画风**：内容 4.33、可接受 73%，
   风格只有 2.87，且没有一张像 waterink-D 那样换掉线性质感。

### 3.1 F 不是单变量实验

F 同时改了**优先声明**与**样式词版本**（压缩词），且 renian 的 compressed 复用了短词、
不是独立压缩产物。所以 F 的胜负只能读作「这份配方整体有效」，
**不能归因到「声明」这一项**。要拆成单变量需要补做「同一短文本 + 有/无优先声明」对照。

## 5. 内容泄露：按参考图「主体强度」分裂

泄露≥3 的比例（带参考图的 C–F 汇总，n=36/风格）：

| 画风 | 参考图内容 | 泄露≥3 比例 | 内容均值 |
|---|---|---|---|
| waterink-style | 水墨山水（技法型） | **25%** | 4.06 |
| fuzichoco-v2 | 蓝紫星空+华丽画框+白鸽+白马 | 50% | 3.17 |
| tinkle-style | 品红粉花海+Q 版少女 | 50% | 3.08 |
| sakurapion-style | 热带花卉+水果芭菲+企鹅+蓝发女性 | 47% | 3.00 |
| renian | 水下+薄荷绿发+气泡+珊瑚 | **69%** | 3.11 |

**A 类｜参考图有具体主体 → D/F 直接把主体搬进画面（泄露 4–5，内容 0–2）**

- `sakurapion-style` D 组：三个 seed 都复刻了参考图的**水果芭菲与热带花卉**，
  蓝长发女角取代请求的港口女性 —— 这是参考内容复制，不是画风迁移。
- `renian` D 组：复刻薄荷绿长发的参考主角，只留下黄外套与自行车当道具。
- `tinkle-style` D 组：换成紫长发 Q 版少女，港口/灯塔/自行车全丢。
- `fuzichoco-v2` E 组：把**画框与白鸽近乎照搬**（prompt 明确禁止复制这些）。

**B 类｜参考图以技法为主 → 画风生效且内容大体守住（泄露 ≤1）**

- `waterink-style` D/E/F 都保住了黄雨衣、自行车、灯塔（内容 4–5），泄露 1；
  代价是场景被改写成「日式山港」，自行车被推到画缘。

### 5.1 最硬的证据：静物组

静物 prompt 明确写着 `No person, no face, no human silhouette`。
sakurapion、renian、tinkle、fuzichoco 的 D/E/F 组**都画进了人**
（sakurapion-E 甚至把请求的茶壶画成那个女孩桌上的道具）。
这不是"风格化处理"，是参考内容压过了显式的内容约束。

## 6. 跨 seed 稳定性（42 / 1234 / 20260927）

- **风格分在三 seed 之间基本稳定**——它是「配方有没有被接住」的开关型量。
- **内容与泄露分波动更大**：同一个 D 组，一个 seed 可能复刻参考主体、另一个只是风格化。
  → **不能**用单 seed 的漂亮结果宣称配方可用。
- 三 seed 全部可接受的组合：A/B/C/G 的多数单元；带画风的只有 **waterink-E（6/9）**、
  waterink-F（4/9）、tinkle-F（4/9）、sakurapion-F（4/9）达到这个水平。
- 9 个单元全不可接受的：**sakurapion-D、renian-D、renian-E、renian-F**。

## 7. 双图实验（G/H）细节

- H 组**没有出现参考主角挤掉内容主角**的情况 —— 内容图在前 + 明确分工确实守住了身份，
  与 A–F 里参考图单独出现时的行为不同。
- 画风增益按画风分裂：waterink 的 H 是唯一换掉整套渲染语言的
  （seed 20260927 那张变成全景水墨山水，内容被压到只剩姿态与衣纹，属「画风成功、内容失守」）；
  sakurapion 的 H 基本没动。
- 服装保真度有系统性损失：sakurapion、renian、tinkle 的 H 把礼服画成更低领口或更多荷叶边。
- 自动指标给出同向信号：H 相对 G 的「与参考图调色距离」——
  waterink 1.71→0.69、renian 1.46→1.00、sakurapion 1.65→1.19、
  fuzichoco 1.18→1.27（略升）、tinkle 1.81→1.77（几乎不动）。

## 8. 自动指标只能当辅助（已验证的失效模式）

- 与参考图的**调色距离下降同时意味着**「画风向参考靠拢」和「参考内容被搬进来」，
  两者在直方图层面不可区分：sakurapion-D（复刻芭菲）的调色距离最低，却是最严重的内容失误。
- 线条/梯度代理无法区分「水墨飞白」与「高噪点画风」。
- 所以本实验**没有用任何自动指标决定分数**，判定全部基于逐图视觉证据。

同类问题也出现在辅助视觉模型上：为了不把未读图变成"未评分"，
另跑了一个视觉模型（`gemini-3-flash-preview`）对剩余单元打分，
但它在 6 个已知单元上与主评分逐维比对**未通过校准** ——
**leakage 维度 0/6 落在 ±1 内**，还把 A 基线（无参考图）评成 style=2、leakage=2。
因此它的分数只作为第二意见记录，未参与任何结论。

| sakurapion | T / P | 1.0 | 5.0 | 0.0 | 3/3 |

## 10. 已验证 vs 仍是推断

**已验证（有本轮真实出图与逐图证据）**

- 参考图单独上传不改变渲染技法；只给样式文字同样基本不改变。
- D/E/F 这一档能显著推动画风向参考靠拢，同时把内容与泄露一起拖下去。
- 泄露按参考图主体强度分裂：抽象参考图（waterink）泄露低，主体明确的参考图泄露高。
- 静物主题是最干净的泄露探针：这些单元里出现人就是违规，而它确实出现了。
- 自动指标不能区分「技法迁移」与「内容照搬」；辅助视觉模型未通过校准。
- 双图分工能守住内容、换不来画风。
- 参数与记录完整可复现：300 个任务 0 失败，独立复核全绿。

**仍是推断（证据不足，别当结论）**

- 「优先声明是不是唯一变量」——F 改了两处，需要补单变量对照。
- 「泄露是否与参考图人物占比成正比」——本轮只有 5 张参考图，分不开。
- 「换实例/换 diffusers 版本是否复现」——跨 seed 已测，跨部署未测。
- 「无主体风格板能否解决泄露」——基于机制的合理猜测，本轮**没做**。
- 各画风「最佳配方」在三个 seed 上并非每张都可接受，只写成「该 seed 下的最佳」。

**明确不做的判断**：不把「人物长得像参考图」或「背景被复制」算作画风迁移成功；
不把自动指标当通过判据；只有 smoke 阶段的结论不写成「稳定迁移」。

## 11. 最小移植方案（纯函数适配设计，未改业务代码）

**本轮没有修改 `D:\code\image-maker` 的任何业务逻辑，也没有改 Qwen 服务实现。**

```python
def build_style_request(
    style_entry: dict,          # 画风条目：长词/短词/压缩词、参考图路径、角色说明
    content_prompt: str,        # 内容 prompt
    content_images: list[str],  # 内容图（可为空）
    mode: str,                  # text_only | ref_style | ref_priority | dual
    *,
    size: tuple[int, int] = (1024, 1024),   # 必须显式传入
    steps: int = 40, cfg: float = 1.0, seed: int | None = None,
) -> dict:  # -> {"prompt": str, "images": [路径...], "params": {...}, "warnings": [...]}
```

**三条硬约束**（缺一条就会重现本轮踩到的坑）：

1. **尺寸显式固定**。有参考图时若不给 `width/height`，管线用 `image[-1]` 推比例 ——
   最后一张参考图的朝向会决定画布。把 `size` 设为必填，并断言宽高是 32 的倍数。
2. **缺图显式回退**。`style_ref` 不存在时不许静默当纯文本跑：降级为 `text_only` 并在
   `warnings` 里写明 `style_ref_missing: <path>`。`dual` 缺内容图时降级并告警。
3. **参考图主体强度先体检**。本轮的泄露几乎都发生在「参考图有具体主体」时，
   所以在需要参考图的 mode 下先判断是否含人脸/人物，放进
   `warnings.reference_has_subject`，让业务选择走 `ref_priority`、换无主体风格板、或退到 `ref_style`。

**建议默认策略（基于本轮证据，仍属推断待补测）**

| 场景 | 建议 mode | 理由 |
|---|---|---|
| 静物 / 无人物内容 | `ref_priority` | 无人可被替换，泄露表现最好 |
| 人物 + 抽象参考图（waterink 类） | `ref_priority` 或 `ref_style` | 两者都能保住内容 |
| 人物 + 有明确主角的参考图 | 默认**不要** `ref_priority`；先 `ref_style`，要画风就换无主体风格板 | D/F 出现内容替换或多出人物 |
| 内容图 + 画风图 | `dual`（内容图在前） | 守住身份，画风增益有限 |

### 11.1 与 prompt 长度上限的关系

移植时必须一起考虑长度预算：本机实测的硬上限是 DiT 位置编码表的 **9216 个位置**，
**文本 token 与参考图的 vision token 共用这一份额**，且越界会把服务打停。
详见 [`PROMPT-LENGTH-LIMIT.md`](PROMPT-LENGTH-LIMIT.md)；
服务端已提供 `POST /v1/tokenize`，控制台有实时计数与发送前拦截。

## 12. 下一步最小验证（按性价比）

1. **单变量补测（约 60 张）**：E 组的同一份短文本，去掉/保留优先声明各跑一次，
   3 主题 × 3 seed × 2 组 → 直接回答「声明是不是那个开关」。
2. **无主体风格板（约 30 张）**：对 sakurapion / renian / tinkle / fuzichoco 各裁一张
   去主体的风格板（列出裁剪来源与坐标），同 prompt 同 seed 替换参考图跑 D/F，
   检验「降低参考主体强度能否在保住画风的同时压低泄露」。
3. **画风-内容权衡曲线（约 45 张）**：在 F 配方下逐步降低参考图权重/尺寸，
   记录三者取舍点，用于定默认档位。
