# 出图质量检查协议（固定 prompt）

本文件是**固定的检查指令**。每次质检都原样使用,不临时改写 ——
判据固定才能跨图对比,也才能在换模型/换参数后重跑同一条基线。

被检图是 `exp/galgame-cg-20260928/out/*.png`；每张另附它的原始 prompt 与角色参考图。

---

## 一、检查顺序（固定，先致命后次要）

顺序不能换：**先看人体，再看语义，最后看渲染。** 先看渲染会被画风带跑，漏掉结构错误。

### A. 人体结构（最高优先级）

| 编号 | 检查项 |
|---|---|
| A1 | 手指/手掌数量与形态：是否多指、少指、手指粘连成块、指节方向反折 |
| A2 | 手臂数量与连接：是否多出一条手臂、手臂与肩膀/躯干连接断开、肘部反折 |
| A3 | 腿的检查：是否多腿、少腿、腿从裙下伸出位置不合理、膝盖反折 |
| A4 | 脚的检查：脚与地面接触是否合理（悬空/穿地）、鞋与脚是否错位、鞋带是否漂浮 |
| A5 | 头颈肩：脖子是否过长/过短/扭曲、肩膀是否塌陷或缺失、头身比是否失调 |
| A6 | 五官：眼睛是否对称、位置是否正确、嘴/鼻是否缺失或错位 |
| A7 | 躯干：腰部是否断折、躯干是否与臀部错位、整体比例是否失衡 |
| A8 | 与道具的接触：握持物是否真的被握住（手与物体是否错位、物体是否穿手） |

### B. 语义与内容（次高）

| 编号 | 检查项 |
|---|---|
| B1 | **人数**：画面里有几个人？与要求是否一致（要求的是"Exactly one girl"时，多一个即为致命） |
| B2 | 人物身份：发色/发型/侧边丸子/白花发饰/瞳色是否与角色设定一致 |
| B3 | 服装：白泡泡袖衬衫 + 蓝色背带裙 + 腰部双金扣 + 裙摆蓝→薄荷绿渐变 + 白色荷叶边，逐项在不在 |
| B4 | 鞋：是否是蓝色蝴蝶结玛丽珍（不是运动鞋/长靴/袜子+平底鞋） |
| B5 | 道具：prompt 点名的道具在不在（镜子、冰茶杯、蛋糕、冰淇淋、购物袋、烟花…） |
| B6 | 场景：地点与时间对不对（室内/街道/海边/天台；白天/黄昏/夜晚） |
| B7 | 动作：要求的姿态有没有画出来（坐/站/倾身/回望/伸手） |
| B8 | **参考图内容泄露**：有没有出现画风参考图里的东西——
    白金发少女、白裙、吊带袜、小提琴、星座连线、悬浮星星/宝石、星空舞台地面、海报式构图 |
| B9 | 场景内容泄露：有没有出现角色参考图里的东西（纯白背景、立绘棚拍感） |

### C. 渲染与画质（最低）

| 编号 | 检查项 |
|---|---|
| C1 | 过曝/死白：是否有大面积纯白无细节区域 |
| C2 | 欠曝/死黑：是否有大面积纯黑无细节区域 |
| C3 | 糊/涂改痕：局部是否有明显糊成一团、结构不可辨 |
| C4 | 复制粘贴感：是否出现两个几乎一样的人物/物件 |
| C5 | 文字与签名：是否出现乱码文字、水印、签名、边框 |

---

## 二、严重度定义（固定口径）

| 等级 | 含义 | 处置 |
|---|---|---|
| **P0** | 人体结构崩坏（A1–A4 任一项明显），或人数不符（B1 多一个完整人物） | 整张作废，必须重出 |
| **P1** | 人体结构明显可疑但不致命（A5–A7），或关键内容错（B2/B3/B4 任一项错） | 优先重出 |
| **P2** | 渲染缺陷（C1–C3）、道具/场景细节缺失（B5–B7） | 可用但需修 |
| **P3** | 轻微瑕疵（C4/C5、无伤大雅的细节偏差） | 可接受 |

> 一条缺陷只记一个等级，取其中最严重的。

---

## 三、输出格式（固定 JSON，便于聚合）

```json
{
  "file": "story-12-goodnight.png",
  "people_count": 1,
  "defects": [
    {"code": "A1", "severity": "P0",
     "where": "≈(x,y) 区域", "what": "两手手指粘连成一团，看不出指节",
     "confident": "high"}
  ],
  "ok": false,
  "worst": "P0",
  "note": "一句话总结"
}
```

- `code` 用上表的 A1–C5；`severity` 用 P0–P3；`confident` 取 high/medium/low。
- **看不出就不写**。宁可少报，不要为了凑数编缺陷 —— 误报会让整份报告失去可信度。
- `worst` = 该图所有缺陷里最严重的等级；无缺陷写 `"none"`。

---

## 四、给检查者的固定指令（原文照用）

> 你是出图质检员。按 `docs/IMAGE-QA-PROTOCOL.md` 的检查表逐项核对这张图，
> **按 A→B→C 的顺序，先人体后语义最后渲染**。
>
> 对每一项，只有在你真的在图里看到了具体证据时才报缺陷，并给出位置与所见。
> 位置用「画面左/中/右 + 上/中/下」或近似像素坐标；不要只写"有问题"。
>
> **不要臆测**：看不清、不确定就把 `confident` 写成 low 或干脆不报。
> 不要因为画风好看就放过结构错误，也不要因为画风不好看就硬找结构问题。
>
> 最后按第三节的 JSON 格式输出，**只输出 JSON，不要额外解释**。

---

## 五、为什么要固定协议

1. **跨图可比**：同一套编号才能统计"哪类缺陷最常见"（例如 A1 手部占比）。
2. **可重跑**：换模型、换 seed、换参数后跑同一协议，能看出是真的改进了还是换了种坏法。
3. **抗漂移**：自由发挥的检查会随当天注意力波动；固定清单把它压住。
4. **可追责**：每条缺陷带 `code` + `where`，能回到图上复核，避免"感觉不对"式的结论。
